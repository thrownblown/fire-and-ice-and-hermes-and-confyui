## 2. "MiniMax H3 Refmod Workflow" — 1x4auud  (20 comments; 13 fetched)
Mined earlier today; ~13 comments added since (2026-10-12 19:34–21:29Z) that were NOT in the
recipe. New, actionable:

- **RefMod token ceiling is the binding constraint (FuckTheActualWhat, AlsterwasserHH):** hit the
  8192-token limit at **~8 images** per refmod. Matches `max_tokens=8192` in our recipe — budget
  refmod image count accordingly.
- **How to REFER to a refmod in the prompt (Karsticles / FreakyMrCaleb / Jwtd29):**
  - Refer by the refmod's NAME, e.g. `<Subject 1> jennaortega wearing the outfit from <Picture 1>`
    for `minimaxh3_jennaortega_v1_refmod.safetensors`. Think of the name as a character token.
  - Mapping seen: a refmod holding MULTIPLE images surfaces as `<Video x>`; one holding audio as
    `<Audio x>`. (Confirm per refmod — see next point.)
  - **"Inspect" node** reports exactly which reference tokens a refmod produces — the reliable
    way to know whether to write `<Video 1>` vs `<Subject 1>` vs the bare name.
  - `Adudeguyman/ComfyUI-Fantastic-MiniMaxH3-PromptBuilder` is a node set that manages refmods +
    text-encode with a nicer UX (Jwtd29 uses it).
- **Voice cloning is the strongest refmod feature (AlsterwasserHH):** a refmod baked with a
  **6-minute** speech sample clones the voice "1:1"; the apply-time audio reference caps at ~30s.
  (Consistent with our recipe: voice is baked at CREATE with a 30s ceiling — a longer/cleaner
  sample is what a good voice refmod wants.)
- **Refmod creation cost knobs (evilpenguin999):** unsure about `resolution` and `pool_h/pool_w`
  for a refmod that stays fast; feeling is ref IMAGES can be quicker than refmods. Unresolved.
- **Combining refs (Bask82 / AlsterwasserHH):** with a good refmod you generally don't need extra
  character images; extra `<Picture N>` slots are for special clothing/props. Motion refmods
  untested by the author.
- Refmods also plug into the obvpm timeline workflow (see §3).

## 3. "Mini Video Editor Timeline Node for H3" — 1wmj6xr  (104 comments; 25 fetched)
obvpm's timeline workflow (extend / prepend / bridge / cut / loop / upscale). New to us:

- **Refmods in the timeline (InariKirin / obvpm):** wire the refmod in and reference it by NAME
  in the prompt (no `<Picture 1>`); items like a sword can still be `<Image 1>`. obvpm's caveat:
  default refmods can't be referenced *directly* — you must describe it so the prompt matches the
  refmod's contents. (InariKirin reports it working; tension with obvpm's own caveat.)
- **Clip bridging is unreliable (dynamix9111):** seamless bridge works a few times then inserts a
  jump cut or an un-prompted angle change; bridging clips that are *visually different* works
  better than bridging two near-identical clips (H3 treats similar end/start as "you want
  something different"). No fix found.
- **Degradation near close-ups (codek_):** large character degradation when subjects approach the
  camera into close-up across a long (40s) timeline; flagged against a workflow-version change.
- Performance caveat (dynamix9111): the timeline stages more VRAM / runs slower than a vanilla
  ref2va graph on a 3090 — traced in that case to loading the wrong (near-identically named) model.
- Correct repo link: `github.com/chanon/comfyui-obvpm-timeline` (the linked `obvpm/...` is wrong).
